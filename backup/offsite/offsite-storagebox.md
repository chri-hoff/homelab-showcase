# Off-site copy: Hetzner Storage Box (#202)

`scripts/backup/sync_offsite_nextcloud.sh` mirrors the Nextcloud Borg repo
(`/mnt/bk_nxc_data/nextcloud`) to a Hetzner Storage Box every night at 03:30 (root cron,
Ansible role `backup`). Docker repo and DB dumps follow after #203.

| What | Where |
|---|---|
| Connection settings | `/opt/docker/secrets/offsite-storagebox.env` (root, 600) |
| SSH key (only for the box) | `/opt/docker/secrets/offsite_storagebox_ed25519` (root, 600) |
| Pinned host key | `/opt/docker/secrets/offsite_storagebox_known_hosts` |
| Log | `/data/backup/ThinkCentre/log/offsite-nextcloud.log`, journal `backup-offsite-nextcloud` |
| Monitoring | Telegram per run, weekly system check (`backup:no-success:offsite-nextcloud`) |

All three files sit under `/opt/docker`, so they are in the Docker Borg backup and come back with
`restore.yml`.

## How it stays safe

- **Never copies a repo Borg is writing to:** takes the same lock as `backup_nextcloud_borg.sh`.
- **Two passes:** first only new `data/` objects (no deletes), then metadata plus `--delete`.
  An interrupted run never leaves archives that reference missing chunks.
- **Check at the end:** a dry run must show no difference between local and remote, otherwise
  the run fails.
- **Snapshots are the protection against a mirrored disaster.** `--delete` faithfully copies a
  broken or encrypted repo. The automatic Storage Box snapshots are managed only in the Hetzner
  Console, not over SSH, so this host cannot delete them.
- Data is encrypted before it leaves the host (`repokey-aes-ocb`); Hetzner only stores
  ciphertext. The sync itself needs no passphrase.

## Setup (once)

1. **Hetzner Console → Storage Box:**
   - Create a sub-account with base directory `offsite-nextcloud`, **SSH support on**, external
     reachability on, Samba/WebDAV off. Only one password exists for it, generated by Hetzner:
     put it in Vaultwarden, it is only needed to install the key.
   - **Snapshot plan:** automatic, daily (e.g. 05:00), keep 7. Snapshots count against the
     1 TB; with a slowly changing photo repo the overhead is small, check after a week.
2. **Key and host key on the ThinkCentre** (fish, as admin):

   ```fish
   sudo ssh-keygen -t ed25519 -N '' -C offsite-storagebox -f /opt/docker/secrets/offsite_storagebox_ed25519
   set BOX u123456.your-storagebox.de   # your box
   ssh-keyscan -p 23 -t ed25519 $BOX | sudo tee /opt/docker/secrets/offsite_storagebox_known_hosts
   ssh-keygen -lf /opt/docker/secrets/offsite_storagebox_known_hosts
   ```

   Compare the fingerprint with the one Hetzner publishes for Storage Boxes before you continue.
3. **Install the public key for the sub-account.** This asks once for the sub-account password
   (`-s` = via SFTP, the box has no full shell):

   ```fish
   sudo ssh-copy-id -p 23 -s -i /opt/docker/secrets/offsite_storagebox_ed25519.pub \
       -o UserKnownHostsFile=/opt/docker/secrets/offsite_storagebox_known_hosts u123456-sub1@$BOX
   ```

4. **Connection settings:**

   ```fish
   printf 'STORAGEBOX_USER=u123456-sub1\nSTORAGEBOX_HOST=u123456.your-storagebox.de\nSTORAGEBOX_DIR=nextcloud\n' \
       | sudo tee /opt/docker/secrets/offsite-storagebox.env
   sudo chmod 600 /opt/docker/secrets/offsite-storagebox.env /opt/docker/secrets/offsite_storagebox_ed25519
   ```

   Optional: `RSYNC_BWLIMIT=<KiB/s>` (e.g. `8000` ≈ 65 Mbit/s) and `MAX_RUNTIME=20h`.
5. **Test the login** (key only, no password prompt allowed):

   ```fish
   sudo sftp -P 23 -i /opt/docker/secrets/offsite_storagebox_ed25519 -o BatchMode=yes \
       -o UserKnownHostsFile=/opt/docker/secrets/offsite_storagebox_known_hosts u123456-sub1@$BOX <<< 'ls'
   ```

6. **Cron:** from the laptop in `ansible/`: `ansible-playbook site.yml -l thinkcentre -K --ask-vault-pass`,
   then `ansible-playbook verify.yml -l thinkcentre -K` (the roles have no tags; the full run is idempotent).

## First upload

~760 GB at about 100 Mbit/s upload is ~17–20 h at best. Start it manually right after the 01:00
backup:

```fish
sudo /data/gitea/homelab/scripts/backup/sync_offsite_nextcloud.sh
```

After `MAX_RUNTIME` (20 h) the run stops with "⏸️ unvollständig" and the next night continues
where it stopped. Until a run completes, the weekly system check reports
`no-success:offsite-nextcloud`. That is intended.

## Restore

**Both Nextcloud disks lost:** copy the repo back to a new `/mnt/bk_nxc_data`, then restore as
usual with the passphrase (Vault `homelab/backup/borg-nextcloud`, Vaultwarden "Borg Nextcloud",
`ansible/restore-secrets.yml`):

```fish
sudo rsync -a --info=progress2 -e "ssh -p 23 -i /opt/docker/secrets/offsite_storagebox_ed25519 -o UserKnownHostsFile=/opt/docker/secrets/offsite_storagebox_known_hosts" \
    u123456-sub1@$BOX:nextcloud/ /mnt/bk_nxc_data/nextcloud/
```

**Mirror itself damaged:** Hetzner Console → snapshots → restore the last good one (with the
main account, snapshots can also be browsed read-only under `.zfs/snapshot/`), then copy back.

### Reading directly from the box (Borg 2 over SFTP)

Borg 2 can read the mirror directly, fetching only the chunks it needs. Used for the restore
test and for pulling single files without a full copy back. First done 2026-11-20.

Prerequisites on the host (root):

- **`python3-paramiko`** (Ansible role `base`). The `borgbackup2` package does not pull it in;
  without it every `sftp://` URL fails with *"Invalid or unsupported Backend Storage URL"*.
- **`/root/.ssh/config`** with the box as a host alias. Borg's SFTP backend (borgstore/paramiko)
  reads `HostName`, `User`, `Port` and `IdentityFile` from there; no ssh options can be passed
  in the URL:

  ```
  Host storagebox
      HostName u123456.your-storagebox.de
      User u123456-sub1
      Port 23
      IdentityFile /opt/docker/secrets/offsite_storagebox_ed25519
      IdentitiesOnly yes
  ```

- **Host key in `/root/.ssh/known_hosts`.** paramiko ignores `UserKnownHostsFile`; unknown host
  keys are rejected:
  `sudo sh -c 'cat /opt/docker/secrets/offsite_storagebox_known_hosts >> /root/.ssh/known_hosts'`

URL: `sftp://storagebox/nextcloud` (one slash = relative to the sub-account's base directory).

**Always use a separate `BORG_BASE_DIR`.** Borg remembers per repository where it was last
seen (`~/.config/borg/security/`). Reading the mirror with root's normal settings asks
*"previously located at /mnt/bk_nxc_data/nextcloud – continue?"*, and answering `y` stores the
SFTP location. The next nightly backup then gets the same question for the local path, cannot
answer it and aborts. If that happened: run `sudo borg2 --repo /mnt/bk_nxc_data/nextcloud
repo-list` once and answer `y`.

**Archive by ID, not by name.** All archives are called `nextcloud` (one series); `extract
nextcloud` fails with *"needed to match precisely one archive, but matched 20"*. Use
`aid:<id>` from `repo-list`.

### Restore test (every 6 months with the DR test)

The passphrase is asked interactively (Vaultwarden "Borg Nextcloud"); paste it into the
terminal only.

```fish
sudo borg2 --repo /mnt/bk_nxc_data/nextcloud repo-list | tail -3        # local, for comparison
sudo mkdir -p /root/restoretest
sudo env BORG_BASE_DIR=/root/restoretest/.borg borg2 --repo sftp://storagebox/nextcloud repo-list | tail -3
# same IDs as local (at most the newest one missing if the 03:30 sync has not run yet)
sudo sh -c 'cd /root/restoretest && BORG_BASE_DIR=/root/restoretest/.borg borg2 --repo sftp://storagebox/nextcloud extract aid:<newest id> tmp/borg_nc_dump'
sudo gzip -t /root/restoretest/tmp/borg_nc_dump/nextcloud_db.sql.gz; and echo "Dump OK"
sudo rm -r /root/restoretest
```

The database dump is small and `gzip -t` checks it completely. Optionally extract a known
file under `mnt/nextcloud/…` too (archive paths have no leading slash).
